# 쓰레드 레퍼런스 수집기

**구매 문의 댓글이 달린 판매자 글을 찾아주는** 크롬 확장입니다.

"어디서 사요?", "링크 좀요", "구매처 알려주세요" 는 **판매자 글에 달리는 댓글**입니다.
이 수집기는 그 댓글을 단서로 **그 댓글이 달린 원글(판매자 글)** 을 찾아내고,
문의가 많이 달린 순서로 줄 세웁니다. 문의가 많이 달린 글 = 실제로 사고 싶게 만든 글입니다.

키워드가 맞는다고 무조건 담지 않습니다. 원글의 **좋아요·댓글 수가 기준을 넘어야** 수집합니다.

새 키워드는 수집한 글에서 **자동으로 발굴해 추천**하지만, **사용자가 승인(컨펌)하기 전에는 절대 수집에 반영되지 않습니다.**

## 핵심 동작

| | |
|---|---|
| 수집 방식 | 브라우저에서 실제로 보고 있는 페이지의 글만 읽음 (비공개 API·크롤러 없음) |
| 대상 페이지 | 홈 피드 / 검색 결과 / 프로필 / 특정 글 페이지 |
| 매칭 | 공백·문장부호·이모지를 제거한 정규화 텍스트 기준 부분일치 (+ 오탐 제외어) |
| 키워드 추가 | ① 시드 그룹 승인 ② 직접 입력 ③ 자동 추천 후보 승인 — **셋 다 승인 필요** |
| 레퍼런스 계정 | 계정을 등록하면 키워드가 안 맞아도 그 계정 글은 전부 수집 (계정별로 끌 수 있음) |
| 검색어 | 자주 쓰는 검색어를 저장해두고 클릭 한 번에 쓰레드 검색 결과 열기 |
| 글/답글 구분 | 쓰레드는 답글에도 글과 같은 주소를 준다. 글·답글을 구분해 표시하고 따로 필터링 |
| 함께 담는 수치 | 조회수 · 좋아요 · 댓글 · 리포스트 · 외부링크 · 본문 이미지 |
| 조회수 | 피드에 안 보이는 경우가 많아, **댓글이 기준 이상인 글만** 상세 페이지로 따로 확인 |
| 자동 스크롤 | 간격·거리를 매번 랜덤으로 흔들어 일정한 기계 리듬을 만들지 않음 |
| 저장 위치 | `chrome.storage.local` (내 브라우저 안에만, 외부 전송 없음) |

## 설치

크롬 웹스토어가 아니라 **폴더를 직접 불러오는 방식**입니다. 자세한 그림 설명과 문제 해결은 [docs/INSTALL.md](docs/INSTALL.md).

**그냥 쓰기만 할 컴퓨터 (윈도우 포함)** — git 없이 zip 하나만 받으면 됩니다.

1. [최신 릴리스](https://github.com/sskk22000-dotcom/threads-collector/releases/latest)에서 `threads-collector-vX.Y.Z.zip` 내려받기
2. **지우지 않을 위치**에 압축 풀기 (예: `C:\Users\<내이름>\chrome-extensions\`)
   — 크롬이 이 폴더를 계속 참조하므로 지우거나 옮기면 확장이 죽습니다
3. `chrome://extensions` → 우측 상단 **개발자 모드** 켜기
4. **압축해제된 확장 프로그램을 로드합니다** → `manifest.json` 이 들어있는 폴더 선택
5. 툴바 퍼즐(🧩) 아이콘에서 압정(📌)으로 고정

**개발도 할 컴퓨터**

```bash
git clone https://github.com/sskk22000-dotcom/threads-collector.git
```

불러올 폴더는 저장소 안의 **`extension`** 폴더입니다.

> 컴퓨터 두 대에서 쓰면 수집 데이터와 키워드 승인 상태는 **각각 따로 저장됩니다.** 자동 동기화되지 않습니다.

## 사용법 (3단계)

1. **키워드 컨펌** — 확장 아이콘 클릭 → `키워드` 탭.
   `직접 구매요청형`·`구매의향/후기형`·`제품명 문의형` 3개 그룹이 기본 승인되어 있고,
   `가격/할인형`·`커머스 플랫폼 언급형` 2개 그룹은 **컨펌 대기** 상태입니다. 필요하면 `승인`을 누르세요.
2. **수집 켜기** — `threads.com` 탭을 연 뒤 팝업 상단의 **수집** 스위치를 켭니다.
   `수집` 탭에서 `자동 스크롤`을 켜면 피드를 알아서 내리며 계속 모읍니다.
   매칭된 글은 페이지에서 파란 테두리 + `수집됨` 뱃지로 표시됩니다.
3. **결과 확인 / 내보내기** — `결과` 탭의 **결과 크게 보기**를 누르면 전체 화면 페이지가 열립니다.
   이미지 썸네일과 조회수·좋아요·댓글·리포스트가 함께 보이고,
   **조회수 ≥ 10,000 / 댓글 ≥ 20** 이 기본 필터로 걸려 있습니다 (자유롭게 조정 가능).
   화면에 보이는 그대로 `CSV` / `JSON` / `MD` 로 내보냅니다.

특정 표현을 집중적으로 모으고 싶으면 `수집` 탭 하단에 **검색어를 저장**해두고 클릭하세요.
쓰레드 검색 결과 페이지가 열리고, 스크롤하는 대로 수집됩니다.

계속 참고하는 계정이 있으면 `계정` 탭에 **`@아이디`(또는 프로필 주소)를 등록**하세요.
기본값으로 그 계정 글은 구매 키워드가 없어도 전부 수집되고, 결과에서 `레퍼런스 계정` 으로 따로 필터링됩니다.

## 키워드 추천 → 컨펌 흐름

```
글 수집 ──▶ 최근 400건 본문 코퍼스
                │
                ▼  2~3어절 n-gram 빈도 + 구매의도 앵커 가중치
        후보 추출 (이미 등록된/거절한 표현 제외)
                │
                ▼
      [ 추천 탭 · status: pending ]      ← 여기서 멈춤. 수집에 안 쓰임
                │
     ┌──────────┴──────────┐
     ▼                     ▼
  승인 → 「내가 추가한 키워드」   거절 → 거절 목록에 기록
        그룹으로 편입              (다시 추천되지 않음)
```

기본값은 스캔 **60건마다** 후보를 다시 뽑습니다(`수집` 탭에서 조정). `추천` 탭의 `지금 다시 뽑기`로 즉시 실행할 수도 있습니다.

시드 키워드 전체 목록과 오탐 방지 규칙은 [docs/KEYWORDS.md](docs/KEYWORDS.md)를, 화면별 상세 설명은 [docs/USAGE.md](docs/USAGE.md)를 보세요.

## 구조

```
extension/
├── manifest.json          Manifest V3
├── icons/
└── src/
    ├── keywords.js        시드 키워드 뱅크 (그룹 · 제외어 · 추천 앵커)
    ├── counts.js          "1.2만"·"3.4K" 파싱 · 임계값 필터 · 상세페이지 조회수 추출
    ├── accounts.js        레퍼런스 계정 핸들 파싱 · 검색어 · URL 생성
    ├── matcher.js         정규화 + 매칭 + 스니펫
    ├── suggest.js         새 키워드 후보 자동 발굴 (승인 전엔 pending)
    ├── storage.js         chrome.storage 스키마 · 기본값
    ├── background.js      상태 소유자: 매칭 · 저장 · 추천 · 내보내기
    ├── content.js         threads.com DOM 에서 글 추출 · 자동 스크롤 · 하이라이트
    ├── content.css
    └── popup.{html,css,js}  수집 / 키워드 / 추천 / 결과 4개 탭
tests/
├── run.sh                 node 없으면 macOS JavaScriptCore 로 실행
└── matcher.test.js        매칭 · 오탐 · 추천 · 계정 · 수치 회귀 테스트 69개
tools/
├── check.sh               manifest + 문법 + 테스트 + 문서 최신 여부 일괄 점검
├── package.sh             배포용 zip 빌드 (점검 통과해야 생성됨)
├── gen_keyword_doc.py     keywords.js -> docs/KEYWORDS.md 생성
└── harness/               크롬에 설치하지 않고 브라우저에서 팝업+background 실행
```

## 테스트

```bash
./tools/check.sh
```

manifest JSON 유효성 → 전체 소스 문법 검사 → 회귀 테스트 69개 → 키워드 문서 최신 여부까지 한 번에 확인합니다.
테스트만 돌리려면 `./tests/run.sh`.

의존성이 없습니다. `node` 가 있으면 node 로, 없으면 macOS 기본 `osascript -l JavaScript`(JavaScriptCore)로 실행합니다.
하나라도 실패하면 종료 코드 1.

키워드를 고친 뒤에는 문서를 다시 생성하세요.

```bash
python3 tools/gen_keyword_doc.py
```

UI 를 고칠 때는 크롬에 매번 다시 로드하지 말고 개발용 하네스를 쓰세요.
`chrome.*` 를 인메모리 스텁으로 대체해 팝업과 background 를 그대로 브라우저에서 돌립니다.

```bash
./tools/harness/serve.sh
```

열린 페이지의 콘솔에서 `await __seed()` 를 호출하면 가짜 글 5건이 수집 파이프라인을 통과합니다.

## 배포용 zip 만들기

```bash
./tools/package.sh
```

`tools/check.sh` 를 먼저 돌려 통과해야만 `dist/threads-collector-v<버전>.zip` 이 만들어집니다.
버전은 `extension/manifest.json` 의 `version` 을 따릅니다. 릴리스로 올리려면:

```bash
gh release create v1.0.1 dist/threads-collector-v1.0.1.zip --title "v1.0.1" --notes "변경 내용"
```

## 내보내기 포맷

- **CSV** — 스프레드시트용. BOM 포함이라 엑셀에서 한글이 깨지지 않습니다.
  컬럼: 수집시각, 작성시각, 작성자, 레퍼런스계정, URL, 그룹, 매칭 키워드,
  조회수/좋아요/댓글/리포스트, 외부링크, 이미지, 본문
- **JSON** — 키워드 설정까지 통째로. 백업·재분석용
- **Markdown** — 그룹별로 묶인 읽기용 리포트

## 주의사항

- 로그인한 내 계정으로 **화면에 실제로 보이는 공개 글**만 읽습니다. 숨겨진 데이터나 비공개 계정 글은 다루지 않습니다.
- 자동 스크롤은 설정한 값을 **기준**으로 매번 0.6~1.8배 사이에서 랜덤하게 쉬고, 가끔 길게 멈추거나 살짝 위로 되돌아갑니다.
  일정한 간격으로 두드리지 않기 위한 것이지, 무제한으로 빨리 돌려도 된다는 뜻은 아닙니다. 기준값 2.5초 이상을 권장합니다.
- 조회수 확인은 댓글이 기준 이상인 글만, 한 번에 하나씩, 8초 이상의 랜덤 간격으로 요청합니다.
- 수집한 글은 다른 사람이 쓴 저작물입니다. 레퍼런스·리서치 용도로 쓰고, 재게시할 때는 출처(작성자·링크)를 함께 남기세요.
- 데이터는 전부 로컬에만 저장되며 어떤 서버로도 전송되지 않습니다.
