# 사용 설명서

## 팝업 화면 구성

확장 아이콘을 누르면 5개 탭이 있는 팝업이 열립니다. 상단에는 항상 **수집 스위치**와 현황(수집 건수 / 스캔 건수 / 최근 수집 시각)이 보입니다.

threads.com 이 아닌 탭에서 열면 “threads.com 탭에서 열어야 수집이 동작합니다” 안내와 함께 피드로 바로 가는 링크가 뜹니다.

---

## 1. 수집 탭

| 항목 | 설명 | 기본값 |
|---|---|---|
| 자동 스크롤로 계속 수집 | 피드를 알아서 내리며 계속 모읍니다. 켜두고 다른 일을 해도 됩니다. | 꺼짐 |
| 스크롤 간격 | **기준값**입니다. 실제로는 매번 0.6~1.8배로 흔들리고, 12% 확률로 2.5~7.5초를 더 쉽니다. 가끔(8%) 살짝 위로 되돌아가기도 합니다. | 2500ms |
| 수집된 글을 페이지에서 표시 | 매칭된 글에 파란 테두리와 `수집됨` 뱃지를 붙입니다. | 켜짐 |
| 최소 글자 수 | 이보다 짧은 글은 아예 무시합니다. | 10자 |
| 답글도 수집 | 아래 설명 참고 | 켜짐 |
| 추천 재계산 주기 | 스캔 N건마다 새 키워드 후보를 다시 뽑습니다. | 60건 |
| 조회수 따로 확인하기 | 아래 설명 참고 | 켜짐 |
| 댓글 N개 이상인 글만 | 이 댓글수를 넘는 글만 조회수를 확인합니다 | 20개 |
| 확인 간격 | 최소 간격. 실제로는 1~2.6배로 흔들립니다 | 8000ms |

### 글과 답글

쓰레드는 **답글에도 글과 똑같은 형식의 주소**를 줍니다 (`/@아이디/post/코드`).
그래서 주소만 보고는 둘을 구분할 수 없고, 그냥 두면 답글이 글에 섞여 들어옵니다.

수집기는 이렇게 판별합니다.

| 상황 | 판별 |
|---|---|
| 글 상세 페이지 | 주소의 글 = **글**, 나머지 = **답글** (확실함) |
| 피드·검색 결과 | "…님에게 답글" 표기가 있으면 **답글** |
| 표기가 없을 때 | **판별 불가** 로 남김 |

결과에는 항상 `글` / `답글` / `판별 불가` 뱃지가 붙고, 결과 페이지의 **종류** 필터로
글만·답글만 골라 볼 수 있습니다.

> **답글을 끄지 않기를 권합니다.** "어디서 사요?", "링크 좀요" 같은 구매 문의는
> 대부분 원글이 아니라 **답글에 달립니다.** 피드만 훑으면 판매자 글만 잔뜩 모입니다.

### 조회수는 왜 따로 확인하나

쓰레드는 피드에서 조회수를 잘 보여주지 않습니다. 그래서 피드만 훑으면 조회수 칸이 비어 있습니다.
전부 채우려면 글마다 상세 페이지를 열어야 하는데, 그러면 요청이 지나치게 많아집니다.

그래서 **댓글이 기준 이상 달린 글만** 큐에 넣고, 수집을 켜둔 동안 **한 번에 하나씩, 8초 이상의 랜덤 간격으로**
상세 페이지를 읽어 조회수를 채웁니다. 한 번 확인한 글은 값을 못 찾았더라도 다시 시도하지 않습니다.

진행 상황은 `수집` 탭 아래쪽과 결과 페이지 위쪽 띠에 표시됩니다.

### 순회 수집

한 곳만 계속 보면 같은 글만 돌고 돕니다. 이 기능을 켜면 **추천 피드와 저장한 검색어들을
번갈아 돌면서** 모읍니다. 켜두고 다른 일을 하셔도 됩니다.

| 항목 | 설명 | 기본값 |
|---|---|---|
| 추천 ↔ 검색 순회하기 | 순회를 켭니다 | 꺼짐 |
| 순회에 추천 피드 포함 | 끄면 저장한 검색어들만 돕니다 | 켜짐 |
| 한 곳에 머무는 시간 | 기준값. 실제로는 0.7~1.4배로 흔들립니다 | 90000ms (1분 30초) |

순서는 **추천 피드 → 검색어1 → 검색어2 → … → 다시 추천 피드** 입니다.
지금 몇 번째를 보고 있는지 설정 아래에 표시됩니다.

> 입력창에 글을 쓰고 있거나 텍스트를 선택한 상태면 페이지를 옮기지 않고 기다립니다.
> 순회는 **수집이 켜져 있을 때만** 동작합니다.

### 검색어

자주 쓰는 검색어를 저장해두고 클릭 한 번으로 쓰레드 검색 결과를 여는 곳입니다.
피드를 훑는 것보다 특정 표현을 집중적으로 모을 때 훨씬 빠릅니다.

- 입력창에 검색어를 넣고 `추가` (엔터도 됩니다). 키워드와 달리 **띄어쓰기가 그대로 유지**됩니다 —
  쓰레드 검색에 그대로 넘어가기 때문입니다.
- 저장된 검색어를 **클릭하면** 새 탭에서 검색 결과가 열립니다. 스크롤하는 대로 수집됩니다.
- 칩 오른쪽 `×` 로 삭제.

아래 드롭다운의 **키워드로 검색**은 승인된 키워드 중 하나를 골라 같은 방식으로 검색합니다.

> 스크롤 간격을 1초 미만으로 두지 마세요. 요청이 몰리면 계정에 일시 제한이 걸릴 수 있습니다.

## 2. 키워드 탭

그룹 단위로 켜고 끕니다.

- **수집중** 뱃지 = 컨펌된 그룹. 이 그룹의 키워드만 실제로 매칭에 쓰입니다.
- **컨펌 대기** 뱃지 = 내가 추천만 해둔 그룹. `승인`을 눌러야 반영됩니다.
- 각 키워드 옆 `×` 로 개별 삭제, 맨 아래 입력창으로 직접 추가할 수 있습니다.
  직접 추가한 키워드는 `내가 추가한 키워드` 그룹에 모입니다.

키워드는 띄어쓰기를 신경 쓰지 않아도 됩니다. `어디서 사셨어요` 로 넣든 `어디서사셨어요` 로 넣든
내부적으로 공백·문장부호·이모지를 지운 형태로 비교합니다.

전체 목록은 [KEYWORDS.md](KEYWORDS.md) 참고.

## 3. 계정 탭 — 레퍼런스 계정

계속 참고하는 쓰레드 계정을 등록해두는 곳입니다.

- 입력창에 **`@아이디`**, **`아이디`**, **프로필 주소**, 심지어 **글 주소**를 넣어도 아이디만 뽑아냅니다.
  (`https://www.threads.com/@banchan/post/abc` → `banchan`)
- 계정마다 **"키워드가 안 맞아도 이 계정 글은 전부 수집"** 체크박스가 있습니다.
  - **켜짐(기본)** — 그 계정 글은 구매 키워드가 하나도 없어도 전부 담깁니다.
  - **꺼짐** — 평소처럼 키워드가 맞을 때만 담되, 결과에 `레퍼런스 계정` 태그가 함께 붙습니다.
- `프로필 열기` 를 누르면 새 탭에서 그 계정 프로필이 열립니다. 스크롤하면 그 계정 글이 수집됩니다.
- 계정 이름 옆 뱃지는 **지금까지 그 계정에서 모은 글 수**입니다.
- 등록된 계정의 글은 **최소 글자 수 제한도 무시**합니다. 짧은 글도 놓치지 않습니다.

결과 탭에서 `레퍼런스 계정` 으로 필터링하면 등록 계정에서 나온 글만 따로 볼 수 있고,
CSV 로 내보내면 `referenceAccount` 컬럼에 어느 계정에서 왔는지 들어갑니다.

## 4. 추천 탭 — 컨펌 흐름

수집한 글에서 자주 나오는 2~3어절 표현 중, 구매의도와 관련된 것만 후보로 올라옵니다.

각 후보에는 **몇 번 나왔는지**, **점수**, **실제 문장 예시**가 함께 표시됩니다.

- `승인` → `내가 추가한 키워드` 그룹에 들어가고, 그때부터 수집에 쓰입니다.
- `거절` → 거절 목록에 기록되어 **다시는 추천되지 않습니다.**
- `지금 다시 뽑기` → 재계산 주기를 기다리지 않고 즉시 후보를 갱신합니다.

**승인하지 않은 후보는 어떤 경우에도 수집에 반영되지 않습니다.** 후보가 쌓여도 결과가 바뀌지 않습니다.

후보가 안 나온다면 대부분 표본이 부족한 경우입니다. 같은 표현이 **2번 이상** 나와야 후보가 됩니다.

## 5. 결과 탭 · 결과 페이지

### 결과 페이지 (권장)

`결과` 탭 맨 위의 **결과 크게 보기** 를 누르면 새 탭에 전체 화면 페이지가 열립니다.
팝업은 좁아서 이미지와 수치를 같이 보기 어렵기 때문에, 실제 정리는 여기서 하는 게 편합니다.

글마다 이렇게 보입니다.

- 본문 이미지 썸네일 (최대 2장 + 나머지는 `+N`)
- 작성자 · 작성 시각 · 레퍼런스 계정 표시
- **본문 전체** (매칭된 키워드는 파랗게 강조)
- **조회 · 좋아요 · 댓글 · 리포스트** — 값을 못 잡았으면 `—`
- 외부 링크, 그룹/키워드 태그, 원문 열기

위쪽 필터 줄에서 조정합니다.

| 필터 | 기본값 |
|---|---|
| 조회수 ≥ | **10,000** |
| 댓글수 ≥ | **20** |
| 좋아요 ≥ | 0 |
| 종류 | 글 + 답글 |
| 그룹 / 정렬 / 검색 | 전체 · 조회수 많은 순 |
| 수치가 안 잡힌 글도 포함 | 꺼짐 |
| 이미지 있는 글만 | 꺼짐 |

`CSV` / `JSON` / `MD` 버튼은 **지금 화면에 보이는 글만** 내보냅니다.
필터를 걸어둔 채 누르면 추려진 결과만 저장됩니다.

> 조회수 조건 때문에 결과가 전부 사라지면, 그냥 비어 보이지 않고 위에 안내 띠가 뜹니다.
> 거기서 `조회수 조건 끄기` 나 `수치 없는 글도 보기` 를 바로 누를 수 있습니다.

### 결과 탭 (팝업 안)

- 상단 드롭다운으로 그룹별 필터. 옆의 `CSV` / `JSON` / `MD` 버튼은 **현재 필터가 적용된 결과만** 내보냅니다.
- 검색창으로 본문·작성자 내 검색.
- 글마다 작성자 링크(새 탭), 매칭된 키워드 하이라이트, 좋아요 수, 외부 링크 개수, 작성 시각이 보입니다.
- `삭제`는 그 글 하나만, `전체 삭제`는 수집 결과 전체를 지웁니다. **키워드 설정은 지워지지 않습니다.**

## 자주 겪는 문제

| 증상 | 원인과 해결 |
|---|---|
| 수집을 켰는데 아무것도 안 쌓임 | ① 쓰레드 탭이 아님 ② 승인된 그룹이 하나도 없음 ③ 피드에 해당 표현이 실제로 없음. `검색 열기`로 키워드 검색부터 해보세요. |
| 확장을 고쳤는데 반영이 안 됨 | `chrome://extensions` 에서 새로고침(↻) 후, 쓰레드 탭도 새로고침하세요. |
| 같은 글이 여러 번 쌓임 | 글 ID 기준으로 중복 제거하므로 정상적으로는 발생하지 않습니다. 발생한다면 쓰레드 DOM 구조가 바뀐 신호입니다 (`content.js` 의 추출 로직 확인). |
| 엉뚱한 글이 잡힘 | `키워드` 탭에서 해당 키워드를 지우거나, `extension/src/keywords.js` 의 `exclude` 에 제외어를 추가하세요. |
| 갑자기 아무 글도 안 잡힘 | 쓰레드가 DOM 구조를 바꿨을 수 있습니다. `content.js` 의 `POST_HREF` 와 `postContainer()` 를 점검하세요. |

## 데이터가 저장되는 곳

전부 `chrome.storage.local` 입니다. 외부로 전송되지 않습니다.

| 키 | 내용 |
|---|---|
| `groups` | 키워드 그룹 + 승인 상태 |
| `posts` | 수집한 글 (기본 상한 5000건, 넘으면 오래된 것부터 삭제) |
| `suggestions` | 컨펌 대기 중인 추천 후보 |
| `rejectedSuggestions` | 거절한 후보 (재추천 차단) |
| `settings` | 수집 옵션 |
| `stats` | 스캔/수집 카운터 |
| `corpus` | 추천 발굴용 최근 본문 400건 |
| `accounts` | 레퍼런스 계정 목록 + 전체 수집 여부 |
| `searchTerms` | 저장해둔 검색어 |
| `viewQueue` | 조회수 확인 대기 목록 |
| `viewFilters` | 결과 페이지 필터 설정 |

확장을 삭제하면 이 데이터도 함께 사라집니다. 중요한 결과는 `JSON` 으로 내보내 두세요.
